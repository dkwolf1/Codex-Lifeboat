# Release checklist

[Nederlands](nl/RELEASE-CHECKLIST.md)

This checklist publishes Codex Lifeboat 3.4.3 as a **pre-release for public
testing**. The tag workflow builds and validates fresh release assets, creates
their checksums and provenance attestations, and publishes the GitHub release.

## Before pushing

- Confirm that `git status --short` contains only intended 3.4.3 changes.
- Confirm that no real backup, database, token, `.env`, EXE, ZIP, or build
  directory is staged.
- Keep the generated `dist` directory locally; `.gitignore` deliberately prevents
  it from entering the repository.
- Do not create the `v3.4.3` tag until the `main` CI run is green.

## Publish with PowerShell

Run these commands from the repository directory:

```powershell
git add -A
git status --short
git diff --cached --check
git commit -m "Prepare Codex Lifeboat 3.4.3 public testing release"
git push origin main
```

Wait until the `main` CI run is green at
<https://github.com/dkwolf1/Codex-Lifeboat/actions/workflows/ci.yml>. Then run:

```powershell
git tag -a v3.4.3 -m "Codex Lifeboat 3.4.3 public testing release"
git push origin v3.4.3
```

The tag triggers `.github/workflows/release.yml`. Do **not** also create a manual
release with the same tag: the workflow creates it and marks it as a pre-release.
Follow it at
<https://github.com/dkwolf1/Codex-Lifeboat/actions/workflows/release.yml>, then
open <https://github.com/dkwolf1/Codex-Lifeboat/releases/tag/v3.4.3>.

## Verify the published release

The release must contain exactly these project-generated assets in addition to
GitHub's automatic source archives:

- `Codex-Lifeboat.exe`
- `Codex-Lifeboat-Windows-x64-Portable.zip`
- `SHA256.txt`

Check that the workflow completed successfully, the release is marked
**Pre-release**, the English release notes are visible, and the ZIP contains the
EXE plus the license, security policy, testing guides, release notes, notices,
and known limitations. Use the `SHA256.txt` generated by the release workflow;
locally built files can have different hashes.

Verify GitHub's build attestation after downloading an asset:

```powershell
gh attestation verify .\Codex-Lifeboat-Windows-x64-Portable.zip --repo dkwolf1/Codex-Lifeboat
```

## Stable-release gate

Do not relabel 3.4.3 as stable solely because automated checks pass. Collect and
record the remaining physical Windows 10 and two-computer round-trip evidence in
the Phase 11 matrix first. Public testers should use the compatibility-result
issue form and must never upload real backups or unsanitized logs.
