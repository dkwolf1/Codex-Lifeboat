# Codex Lifeboat 3.4.13 — safer project backups on Windows and WSL

[Nederlands](../nl/releases/v3.4.13.md)

This update addresses the project backup failures in [issue #15](https://github.com/dkwolf1/Codex-Lifeboat/issues/15).

- The preview marks unsafe broad roots and shows when a project is nested
  under another root. Equivalent WSL UNC spellings of the same root are copied
  once. Separately registered nested roots remain selectable.
- The project selection screen offers opt-in exclusions for `node_modules`
  and `.venv`. The backup report lists omitted entries. The size shown in
  the preview is an estimate before these exclusions.
- The project preflight checks readability before copying payloads. When
  required paths are blocked, `reports/project-read-errors.json` lists the
  issues found. The selection screen allows users to exclude an affected
  project while keeping its conversation history.
- Recognized symbolic links and junctions are reported and skipped. When a
  WSL path fails to read, Lifeboat can ask the owning distro whether it is a
  symbolic link. Regular files that remain unreadable block the backup.
- Copy operations retry short Windows locks. Where a byte copy succeeds
  after `copy2` returns `EINVAL`, the report warns that metadata may differ.
- Codex's managed `packages/standalone` and `packages/app-server-daemon`
  installations stay local. Other entries under `packages` remain portable.
