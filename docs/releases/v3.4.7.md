# Codex Lifeboat 3.4.7 — compressed duplicate resolution

[Nederlands](../nl/releases/v3.4.7.md)

Codex Lifeboat 3.4.7 fixes a duplicate-rollout edge case reported during
follow-up testing of issue #8.

## Fixed

- Recognizes a physical `rollout.jsonl.zst` as the post-compression equivalent
  of an SQLite `threads.rollout_path` that still names `rollout.jsonl`.
- Selects the compressed rollout only when it is the unique database-backed
  candidate in the expected active or archived collection and has a valid
  SHA-256 hash.
- Preserves every non-canonical candidate under `codex/unreferenced-rollouts`
  without modifying or deleting source rollouts.
- Keeps genuinely ambiguous duplicates fail-closed.

## Validation

- Added an end-to-end regression with three distinct `.jsonl.zst` rollouts that
  share one thread ID while SQLite references the original `.jsonl` filename.
- Verified canonical selection, preservation of both alternatives, byte-exact
  copied payloads, source immutability, and independent package validation.
- All 87 source checks and all 12 automated Windows compatibility scenarios pass.

## Download

Download `Codex-Lifeboat-Windows-x64-Portable.zip`, extract it completely, and
run `Codex-Lifeboat.exe`.

The executable remains unsigned. Keep issue #8 open until the reporter confirms
backup verification and restoration with the affected profile.
