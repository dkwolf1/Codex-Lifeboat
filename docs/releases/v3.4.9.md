# Codex Lifeboat 3.4.9 — inaccessible dependency metadata

[Nederlands](../nl/releases/v3.4.9.md)

Codex Lifeboat 3.4.9 fixes repeatable backup failures when Windows denies
directory enumeration for installed Python distribution metadata below a Codex
project dependency root.

## Fixed

- Continues only when an access-denied error affects a versioned `*.dist-info`
  directory directly below `.chatgpt-projects/**/_deps`.
- Keeps conversation rollouts, project registrations and every readable sibling
  file mandatory and included.
- Writes `reports/skipped-reconstructable-directories.json` with the source
  directory, intended backup path, error type, classification and
  `contentsEnumerated: false`.
- Protects that report with the package SHA-256 manifest and verifies it during
  independent backup validation.
- Shows the omission as a distinct warning in the Dutch and English GUI.
- Keeps every other inaccessible directory fatal, including similarly named
  directories outside `_deps`, non-`.dist-info` content and non-permission
  enumeration failures.

Because Windows denied enumeration, Lifeboat cannot list files it was not allowed
to inspect. It therefore reports the exact omitted directory and explicitly
records that the contained file count is unknown.

## Validation

- Added an end-to-end backup, independent validation and restore regression for
  `.chatgpt-projects/work/_deps/pillow-12.3.0.dist-info` with simulated WinError 5.
- Added negative tests for nearby paths and error types that must remain fatal.
- All 90 source checks and all 12 automated Windows compatibility scenarios pass.

## Download

Download `Codex-Lifeboat-Windows-x64-Portable.zip`, extract it completely, and
run `Codex-Lifeboat.exe`.

The executable remains unsigned. Keep the old computer and an independent
recovery copy unchanged until the destination has passed post-restore checks.
