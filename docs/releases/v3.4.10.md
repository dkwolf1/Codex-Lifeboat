# Codex Lifeboat 3.4.10 — reviewed dependency preflight

[Nederlands](../nl/releases/v3.4.10.md)

Codex Lifeboat 3.4.10 replaces the narrow 3.4.9 `*.dist-info` exception with a
complete, read-only preflight of every reachable Codex project dependency path
below `.chatgpt-projects/**/work/_deps`.

## Fixed

- Discovers all reachable access-denied dependency files and directory subtrees in
  one preflight instead of stopping at one blocked package per backup attempt.
- Shows the complete relative-path list in a scrollable review window before the
  destination is selected.
- Requires explicit approval of that exact set. Canceling the review excludes
  nothing and creates no backup.
- Repeats the preflight immediately before copying. A new, removed or changed
  exclusion invalidates the approval and stops the backup.
- Permits exclusions only within `.chatgpt-projects/**/work/_deps`. Conversations,
  project registrations, ordinary project data and every path outside that boundary
  remain mandatory.
- Keeps sharing violations, non-permission errors and unknown path types fatal.
- Writes hash-protected `reports/dependency-preflight.json` and, when approved paths
  are excluded, `reports/dependency-exclusions.json`.

## Restore safety from issue #8

- Peak free-space planning now includes logical payload bytes, conservative
  per-file allocation overhead, and a safety reserve. This matters for packages
  containing millions of small files.
- The reviewed plan is refreshed immediately before the safety copy is created,
  and large project/session writes recheck the runtime reserve.
- A full-disk error while writing the failure journal no longer prevents automatic
  rollback from being attempted; the original failure remains the raised cause.

These changes address the confirmed ENOSPC safety failure reported in issue #8.
They do not claim that the reporter's incident-specific rescue utility, Defender
observations, nested-project patch, or performance targets have been incorporated.

If Windows denies enumeration of a directory, Lifeboat reports that entire
directory subtree as the exclusion scope. It never claims to know filenames it was
not allowed to enumerate. Excluded dependency payload must be reconstructed by Codex
or the relevant package manager after restore.

## Validation

- Added simultaneous simulated WinError 5 failures for `PIL` and
  `pillow-12.3.0.dist-info` under the same project dependency root.
- Added negative coverage for missing approval, changed preflight results, ordinary
  project data, sharing violations and non-access-denied errors.
- Added end-to-end backup, independent validation, restore and tamper rejection for
  the approved exclusion reports.
- All 95 source checks and all 12 automated Windows compatibility scenarios pass.

## Download

Download `Codex-Lifeboat-Windows-x64-Portable.zip`, extract it completely, and run
`Codex-Lifeboat.exe`.

The executable remains unsigned. Keep the old computer and an independent recovery
copy unchanged until the destination has passed post-restore checks.
